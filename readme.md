# Homilia Messenger

Homilia Messenger is a desktop messenger for experimenting with conversations with AI agents. Every contact is an AI persona. You describe who they are, point them at an agent, and chat with them as if they were that person. You can change the agent or model behind a contact and carry on the same conversation.

See the [product specification](docs/product_specification.md) for the full direction.

## Current Features

- **Messenger:** a conversation list (most recent first, searchable, with message previews) and a chat thread with grouped message bubbles, timestamps, a typing indicator, and a composer (Enter sends, Shift+Enter adds a line). Start a chat with any contact, continue an existing one, or delete it. Each contact has one private chat, stored locally. The small button beneath the latest reply's photo asks the contact to keep the conversation going without you writing anything.
- **Group conversations:** invite a second contact from a chat to start a group with the two of them; your private chat is left as it was. Each contact keeps their own personality, model, voice, and memories, and remembers what you told them privately without the other being told. Contacts answer when spoken to by name, may respond to each other, or stay quiet, in rounds of at most three messages; now and then, while the group is open, one may start a conversation, which can be turned off. Contacts on the same model share one loaded copy of it. See [group conversations](docs/group_conversations.md).
- **Memory:** contacts with a model have two kinds of memory. The *recent conversation*, the latest messages themselves, is given to the model word for word with each reply, but only as much as fits. Once older messages no longer fit, the contact's model condenses them in the background into *long-term memories*: the lasting things you told them (names, plans, dates, promises), each stored separately in the app's local SQLite database and kept however many there are. With each reply, the contact recalls only the long-term memories that relate to what you're talking about. When an optional embedding model is downloaded in Settings (such as BGE small or Nomic), each memory is turned into a vector embedding on your computer and stored in SQLite beside it. Your latest messages are embedded the same way and compared with them, so memories are recalled by meaning rather than shared words. Without an embedding model, or for memories not yet embedded, recall falls back to matching words. Open the memories from the chat header to read, correct, add, or delete what a contact remembers.
- **Optional spoken replies:** download and enable Kokoro in Settings (326 MB, Apache 2.0), then choose a contact's voice. The 28 American and British English voices are included with the app. Voice choices are filtered by gender; changing gender keeps the previously saved voice. Turn speech on from the chat ribbon to hear new replies alongside their text; in a group, each contact speaks in their own voice, in turn. Speech starts off after relaunch, and switching chats or leaving the Messenger page turns it off and cancels playback. Everything runs locally, without an account or GPU.
- **Optional generated contact photos:** describe a person ("an older man with a long white beard and glasses, wearing a plaid shirt in his workshop") and generate a polished, slightly stylized 512×512 portrait on your own computer, then use it, generate another from the same description, or cancel without changing the contact. Download DreamShaper 8 LCM in Settings first (1.8 GB, CreativeML Open RAIL-M); a photo takes about 20 seconds on a fast desktop CPU and about 4 GB of memory, with no GPU or account. Other Stable Diffusion 1.x GGUF models can be added from Hugging Face for experimenting, after the app checks each file's header. Runs with [stable-diffusion.cpp](https://github.com/leejet/stable-diffusion.cpp), included with the app. Verified on Windows; Linux is included but not yet verified. See [contact photo generation](docs/image_generation.md).
- **Persona contacts:** add, edit, and delete contacts with a name, nickname, birthday (required; personas must be 18 or older, and their age is calculated from it), gender (male or female), relationship to you (such as "Grandfather" or "Colleague"), personality, background, photo, and favorite flag.
- **Profile:** tell your contacts who you are: your name, age, gender, a few words about yourself, and a profile photo. Every contact knows it, along with how they are related to you, so your grandfather knows he is texting his grandson.
- **Local agents:** contacts can be answered by a small language model running on your own computer, with no server, account, or GPU. Download a model from Settings (Phi-3.5 mini, 2.8 GB, or Phi-4 mini, 4.9 GB, both MIT-licensed builds published by Microsoft), then choose it as a contact's agent in the contact editor. Replies are written in character from the contact's persona and the recent conversation. Downloads resume if interrupted and are checked against published SHA-256 hashes. Models run with [ONNX Runtime GenAI](https://github.com/microsoft/onnxruntime-genai).
- **Models from Hugging Face:** add any GGUF model from Hugging Face in Settings, by repository name or address, and choose among its quantizations (the app recommends Q4_K_M, and briefly explains the size-quality tradeoff of the others). Entering an original model's repository, which has no GGUF files, offers the GGUF conversions Hugging Face's model tree records for it; when it records none, repositories with similar names are offered but marked unconfirmed. Discovery reads only repository metadata and downloads nothing. Added models run with [llama.cpp](https://github.com/ggml-org/llama.cpp) through [LLamaSharp](https://github.com/SciSharp/LLamaSharp), are pinned to the repository revision they were added at, and are verified against Hugging Face's published SHA-256 hashes. Gated repositories work with a Hugging Face access token, kept in the operating system's credential store.
- **Optional web search:** contacts can look up current information, such as a new release or recent news, when a message asks for it or asks about something recent. Off by default; turn it on in Settings with your own [Tavily](https://tavily.com) API key (kept in the operating system's credential store). Only a short query made from your latest message is sent, a local credit budget keeps usage in check, and a globe beside a reply shows what was looked up and the sources. See [web search](docs/web_search.md).
- **Simulated replies:** contacts without an agent reply with random canned text, so the messenger works without any model.
- **Agent assignment:** each contact records the provider and model that speak for it, and each reply records which one wrote it. Changing a contact's agent keeps its conversation.
- Searchable contact list with favorites first, plus unsaved-change protection when switching contacts.
- Theme selection (System, Light, or Dark) that is remembered between sessions.
- Local SQLite persistence and rolling diagnostic logs.

## Privacy

All contacts and conversations are stored locally on your machine. Local chat, speech, and image models run entirely on your computer, so chatting with them or generating a photo sends nothing anywhere. Otherwise the only network use is downloading a model you choose: chat and image models from Hugging Face and Kokoro from GitHub. If you turn on web search, short search queries made from your messages (never your conversations, memories, or profile) are sent to Tavily; see [web search](docs/web_search.md).

## Development

- The solution is `src/HomiliaMessenger.slnx`.
- Run `dotnet build/cake.cs` from the repository root to restore, build (Release) and test the solution; it uses [Cake.Sdk](https://cakebuild.net/docs/running-builds/runners/cake-sdk), pinned in `global.json`. Pass script arguments after `--` to change what runs, for example `dotnet build/cake.cs -- --target=Build --configuration=Debug` (without the `--`, `dotnet` consumes `--configuration` itself and the build stays in Release). Every run ends by deleting any empty `TestResults` folders in the repository; `--target=CleanTestResults` does only that.
- Run the app with `dotnet run --project src/HomiliaMessenger.DesktopApp`.
- Tests in the `LocalModel` category run the real Phi-3.5 mini model when it is downloaded on the machine (in the application data directory's `Models` folder) and are inconclusive otherwise. Exclude them with `--filter "TestCategory!=LocalModel"`.
- Tests in the `ImageModel` category generate with the real DreamShaper 8 LCM checkpoint, and compare an image with the local portrait experiment's pixel for pixel. Set `HOMILIA_IMAGE_TEST_MODEL` to the checkpoint's path, or download it in Settings; they are inconclusive otherwise. Exclude them with `--filter "TestCategory!=ImageModel"`.
- Building downloads the pinned stable-diffusion.cpp CPU runtime for image generation (18 MB for Windows, 29 MB for Linux) once, checks its SHA-256 hash, and includes it in the build and publish output; see [contact photo generation](docs/image_generation.md#the-native-runtime). A build without network access still succeeds, without image generation; a publish fails instead.
- Tests in the `LocalSpeech` category synthesize real Kokoro audio without playing it. Set `HOMILIA_KOKORO_TEST_MODEL` to the official `kokoro.onnx` file from [KokoroSharpBinaries v2.0.0](https://github.com/Lyrcaxis/KokoroSharpBinaries/releases/tag/v2.0.0) to run them; they are inconclusive otherwise. Routine speech tests use fake downloads and playback. Windows playback uses NAudio; Linux/macOS playback requires a working OpenAL audio backend.
- As configured in the `Directory.Build.props` file, every project targets .NET 10, disables implicit using directives, and treats all types as not-nullable unless explicitly declared.
- The desktop application is built on the [Avalonia](https://github.com/AvaloniaUI/Avalonia) UI framework.
- Follow the [development conventions](docs/development_conventions.md).
